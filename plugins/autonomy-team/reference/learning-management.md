# 업무 중 학습·에이전트 관리 절차

종료 응답의 management.status는 not-requested, not-stored, work-unverified, review-incomplete, review-recorded를 구분한다. review-incomplete의 missing을 보고 교훈·역량 분류·역할 검토 중 빠진 항목을 알린다. 누락을 필요 없음으로 해석하지 않는다. review-recorded도 작업자가 제공한 검토 데이터이며 독립 검증이나 개선 확정이 아니다. 검토 누락을 보완하려고 닫힌 요청의 과거 기록을 변경하거나 가짜 근거를 생성하지 않는다.

이 절차는 기존 autonomy-team과 runtime을 연결한다. 모델 가중치 재훈련, 새 권한, 예약 작업, 별도 상시 실행을 만들지 않는다.

1. 현재 요청과 실제 프로젝트를 확인하고 승인·중단·보존 조건을 따른다. 승인 영역 밖의 자료 공유는 하지 않는다. 실제 시작 식별자가 없으면 도구 전송·직접 입력 경로를 구분하여 미확인으로 보고한다. 과거 키나 새 가짜 키를 사용하지 않는다.
2. dispatch 전에 현재 업무의 역량을 판단한다. gap과 contextTags는 실제 요구사항에서 얻은 안전한 분류만 사용한다. 같은 역량의 기존 gap을 재사용한다. 식별 근거가 없으면 생략한다. gap이 없으면 교훈 저장은 가능하지만 역할 생명주기 평가는 진행되지 않는다. 분류는 dispatch 이후 고정한다.
3. dispatch 결과의 reusable·cautions·management·adaptation을 구분한다. 교훈을 현재 업무에 맞춰 검토하고, 관련 교훈만 적용한다. 공유 승인과 맥락 조건이 모두 맞을 때만 다른 프로젝트의 절차를 사용한다. 원문·고객 자료·개인정보를 교훈으로 복사하지 않는다.
4. generatedAgent가 선택되면 read-role과 해시 확인 후 절차를 적용한다. 단계 도구·산출물 증거를 연결한다. 역할이 없다고 매번 생성하지 않는다. 꺼진 역할을 임의로 다시 켜거나 권한을 확대하지 않는다.
5. 실제 업무 산출물을 재읽고 요구사항을 의미 검수한 뒤 verify_artifacts를 실행한다. 실패와 unknown을 성공으로 바꾸지 않는다. 새 채팅·다른 프로젝트의 일반 요청은 서로 별도로 확인한다.
6. 성공에는 실제 업무에서 얻은 bounded lesson을 추출한다. 개선이 확인된 제안만 improvement로 표시하고, 일반화 가능한 절차만 portable과 적용 조건을 갖춰 개인정보 검수 후 공유한다. 환경·권한 실패는 역할 역량 부족 학습으로 저장하지 않는다. 성공이 미확인이면 unverified로 종료한다.
7. 교훈만으로 충분한지 먼저 판단한다. lesson.agentReview의 action은 lesson-only → refine-existing → create-role 순서로 검토한다. reason에 중복·필요성·관리 부담을 설명하고 reviewedRoles에 실제 읽은 기본 팀과 관련 역할만 기록한다. 확인된 수정 횟수와 품질 정의·산출물 증거가 있는 improvement 제안은 수정 1건으로 pilot을 만들 수 있다. 기존 확정 역할 개선은 전체 절차 실행 증거도 필요하다. 판단 근거가 없는 기존 제안은 별도 업무 2건 기준을 유지한다. finish가 반환한 adaptation을 확인한다. pilot은 개선 확정이 아니다. 실패 시 비활성화·복귀하고 이력을 보존한다. 이전 방식과 별도 과제의 같은 품질 기준으로 비교한다. 기한·한도·잠금에 막히면 우회하지 않는다.
8. 한 요청에서 승인된 업무와 검증이 끝나면 종료한다. 변화 없는 같은 실패 검사를 반복하지 않는다. 장기 개선 효과는 실제 업무 누적 후 판단한다. 사용자는 매번 학습·에이전트 관리 명령을 입력할 필요가 없어야 하지만, 이 문서 존재만으로 모든 호스트 경로의 자동 실행을 보장하지 않는다.

management 응답은 조건 안내이며 실행 영수증이 아니다. procedureExecutionVerified는 false를 유지한다. 현재 지원되는 사건의 자동 호출, 산출물, 저장, 반환·적용, 역할 시험 효과를 각각 보고한다.

## 사용자 요청을 기다리지 않는 검토

실제 업무를 끝낼 때 성공 결과뿐 아니라 사용자 교정, 실패, 반복 수정, 비효율을 함께 대조한다. 사용자가 따로 오류 분석이나 학습을 요청해야만 검토하는 방식으로 운영하지 않는다. 최신 예시의 도구명이나 업무 종류를 모든 역할의 생성 기준으로 고정하지 않는다. 같은 역량의 기존 공통 역할을 먼저 읽고, 절차 저장만 필요한지 기존 역할 개선이 필요한지 새 역할이 필요한지 근거를 남긴다. 설명만으로 검증 성공이나 교훈 적용을 만들어내지 않는다.

새 역할은 세션별 복사본으로 만들지 않는다. 공통 등록부의 기존 역량 식별자와 적용 조건을 확인하고 중복 생성을 막는다. 단, 이름만 다른 의미상 중복 전체를 실행기가 자동 판별하는 것은 아니므로 작업 모델의 실제 검토가 필요하다. 공통 역할 재사용과 평가 근거 공유는 별개다. 절차 공유가 승인된 프로젝트의 별도 eval- 과제는 각 프로젝트 안의 이전 방식·시험 역할 결과와 해시·동일 품질 기준·절차 증거를 대조하여 공통 역할 평가에 사용한다. 원문·작업 기록을 공통 저장소로 복사하지 않는다. 읽기 실패·환경 실패·범위 초과는 확정을 보류한다.

시작 management.nextActions와 종료 management.nextActions를 확인하고 필요한 조치를 실제 수행한다. 누락 항목을 성공으로 바꾸지 않는다. common-procedure-review-required는 공통화 전 개인정보와 적용 범위 검토가 필요하다는 뜻이다. portable을 자동으로 붙이지 않는다. 이미 닫힌 요청을 다시 쓰지 않고 다음 실제 관련 업무에서 누락을 예방한다.

시작 management.pendingReviewSelection은 같은 분야·역량·정규화한 문맥의 닫힌 학습 요청 중 최근 최대 24개를 읽기 전용으로 검사한다. 검토 누락의 경험 식별자와 고정 조치 이름만 반환하며 원문을 복사하지 않는다. truncated는 전체 검사 미완료다. 이것은 다음 업무의 검토 안내이며 과거 종료 기록을 다시 쓰거나 과거 역할 검토를 소급 성공 처리하지 않는다. 실제 관련 조치를 수행하고 현재 업무의 새 결과로 검증한다. 실패·미검증 업무는 성공 교훈 보완 대상으로 바꾸지 않는다.

확정된 공통 역할도 공유 승인이 있는 프로젝트의 실패를 확인한다. 품질·역할 부족 실패는 기존 보호·사용 중 잠금·복귀 규칙을 따르고, 환경 실패는 역할을 삭제하거나 역량 부족으로 바꾸지 않는다. 동료 프로젝트를 읽을 수 없거나 조사 한도를 넘으면 추가 개선을 진행하지 않고 검토 미완료로 보고한다. 승인되지 않은 프로젝트를 탐색하지 않는다.

pilot이 생성되면 생성 근거와 독립된 비교 과제의 입력·수용 기준을 정하고 기존 방식과 비교한다. 사용자가 맡긴 업무를 바꾸거나 평가 결과를 꾸미지 않는다. 필요한 비교 과제가 아직 없으면 효과 미확인으로 표시하고 다음 관련 업무에서 확인한다. 평가 실패는 이전 검증 상태로 복귀하며, 중단·권한·잠금 문제를 성공으로 바꾸지 않는다. 확인되지 않은 사용 중 표시나 잠금을 임의로 제거하지 않는다.
