# 경험 개선

훅 turnKey가 있는 작업은 finish의 lesson으로 실제 성공 절차를 남긴다. lesson 형식은 agent-builder의 spec과 같다. 원문·도구 응답·개인 기억을 수집하지 않는다. 다음 SessionStart/dispatch에서 반환된 lesson은 증거 파일 해시를 다시 검사한 최근 성공 최대 3개다. 변경되거나 없는 증거의 lesson은 제외된다. 직접 record한 지표는 호출자가 보고한 값이고 훅 finish의 시간은 측정값이다. 어느 경로도 의미적 품질의 독립 검증을 대체하지 않는다.

개인 기억과 분리된 프로젝트 .sodam-agent에서 구조화된 최소 결과만 관리한다. 완료 문장 자체를 성공 데이터로 쓰지 않는다. 역할·환경·권한·품질 원인을 분리한다. 후보 생성→템플릿 검증→pilot→원인 발견에 사용하지 않은 서로 다른 2개 작업의 기존 방식과 쌍별 비교→확정 순서를 따른다. 품질·시간·수정이 악화되면 rollback한다. 기준·권한·실패 기록을 자동 변경하지 않는다. 실제 작업 품질은 별도로 검토한다.

사용자·상위 지시와 원본 보존을 우선한다. 현재 권한·도구별 쓰기 게이트를 따르며 내부 관점과 독립 검증을 구분한다.
