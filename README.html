0.3.6 구조화된 조율과 완료 기록 (2026-10-09)

1. SoDam-Agent-Codex란?

이 프로젝트는 Codex 안에 전문가별 업무 설명서를 추가하는 도구 상자입니다. 예를 들어 docs-team을 설치한 뒤 “문서팀으로 초보자 안내서를 작성해줘”라고 요청하면, 문서 작성·편집·사실 확인 역할의 지침을 작업에 적용합니다.

알아둘 점은 다음과 같습니다.

  • 자동으로 모든 팀이 항상 실행되는 것은 아닙니다. 설치한 플러그인과 요청 내용에 따라 필요한 스킬을 사용합니다.
  • 팀 스킬은 작은 요청이면 필요한 역할만 사용합니다.
  • 사용자가 팀 작업이나 병렬 처리를 명시적으로 요청하지 않는 한 서브에이전트를 자동으로 만들지 않습니다.
  • 삭제, 배포, 외부 전송처럼 영향이 큰 작업은 사용자 권한과 확인이 필요합니다.
  • AI 결과는 검토가 필요합니다. 특히 법률, 보안, 개인정보, 배포 결과는 사람의 최종 확인이 필요합니다.

  • npm publish: 이 저장소는 private: true인 Codex 플러그인 마켓플레이스이며 npm 패키지 게시물이 아닙니다.

단, Context7 MCP를 처음 실행할 때 npx가 npm 레지스트리에서 고정 버전 패키지를 내려받을 수 있으므로 인터넷 연결이 필요할 수 있습니다.

8. 자동 학습·에이전트 운영

한 번 명시적으로 켠 공통 자동 운영은 직접 끌 때까지 유지됩니다. 새 채팅·다른 업무 프로젝트에서도 신뢰된 시작 훅이 현재 위치를 확인하면 자동 연결합니다. 매주 다시 켜는 방식이 아닙니다. 기존 기간제 프로젝트·영역은 자동 이전하지 않으므로 별도 이전 여부를 확인합니다. 저장·역할·재시도 한도와 파일 접근 권한은 계속 적용됩니다.

처음 한 번 설정하기

설치 후 autonomy-team/hooks/hooks.json과 연결 실행 파일을 검토하고, 사용하는 Codex의 훅 신뢰 절차를 따르세요. 다른 플러그인을 일괄 신뢰하는 뜻은 아닙니다. CLI와 Desktop의 실제 연결은 각각 확인합니다.

일반 사용자는 Codex 채팅에 다음과 같이 요청할 수 있습니다. “SoDam의 공통 자동 운영과 에이전트 자동 시험 적용을 끌 때까지 켜줘. 현재 설치 경로와 설정을 확인하고 기존 기록을 보존해줘.” 실제 도구와 권한이 있어야 설정할 수 있으며 요청 문장만으로 활성화가 증명되지는 않습니다.

직접 설정하려면 업무 프로젝트 안에 automatic-enable.json을 만들고 다음 내용을 저장합니다. 이 숫자는 예시 한도이며 기간을 뜻하지 않습니다.

{"authorize":true,"enabled":true,"autoPilot":true,"maxAgents":8,"maxExperiences":200,"maxRetries":1}

아래의 설치 위치와 업무 프로젝트 경로를 실제 경로로 바꾸세요. 명령은 터미널에, JSON은 파일에 넣습니다. 개인 승인 파일을 공개 저장소에 올리지 마세요.

node "설치 위치/runtime/cli.mjs" automatic-configure "업무 프로젝트 절대 경로" automatic-enable.json
node "설치 위치/runtime/cli.mjs" automatic-inspect
node "설치 위치/runtime/cli.mjs" diagnose "업무 프로젝트 절대 경로"

설치 위치는 실제 autonomy-team 폴더입니다. 다운로드 원본으로 실행할 경우 plugins/autonomy-team/runtime/cli.mjs를 사용합니다. 공통 설정은 현재 PC 사용자의 홈 아래 .sodam-agent-automatic/policy.json에 저장됩니다. 기존 독립 프로젝트는 automatic-adopt, 기존 승인 영역은 area-persistent로 명시적으로 이전합니다. 상세 입력과 되돌리기는 자동 운영 안내를 따릅니다. 기간제 모드를 선택한 기존 정책은 그 기간이 유지됩니다.

끄기·상태 확인

automatic-disable.json에 {"authorize":true,"enabled":false}를 저장하고 위 automatic-configure 명령의 마지막 파일명을 바꾸면 다음 정책 검사부터 중지합니다. 기록은 보존합니다. 다시 켤 때는 enable 파일을 사용합니다.

활성은 정책·한도가 업무를 허용한다는 뜻입니다. 작업 완료나 개선 효과를 증명하는 배지는 아닙니다. 비활성·대기·한도 도달·미확인도 구분하며, 앱에 고정된 버튼이 아니라 답변 속 표시입니다.

학습·자동 시험·역할 관리

학습은 검증한 경험을 절차로 저장하고 다음 관련 업무에서 활용하는 것입니다. AI 모델 자체를 다시 훈련하지 않습니다. 자동 시험 적용은 근거가 충족된 새 역할·개선 역할을 pilot 후보로 사용해 보는 기능입니다. 모든 역할이 매번 생성되거나 실행되는 뜻은 아닙니다.

실제 결과 재읽기 → 검사 → 교훈 저장 → 관련 후속 요청에서 조건 확인·적용 순서입니다. 반환만 된 교훈과 실제 적용은 구분합니다. 환경·권한 오류는 실력 부족으로 학습시키지 않습니다. 별도 업무 근거와 동일한 비교 기준을 충족해야 후보를 만들고 확정합니다. 실패 후보는 비활성화하고 이전 검증 역할로 복귀하며 이력은 보존합니다. 사용자가 관리 명령으로 직접 끈 버전은 승인 후 복구할 수 있지만, 품질 실패로 꺼진 버전을 근거 없이 다시 켜지는 않습니다.

공통 운영을 켜도 프로젝트 간 자료 공유가 켜지는 것은 아닙니다. 검수된 일반 절차만 별도 영역 공유 동의와 업무 조건이 맞을 때 조회합니다. 원본·개인정보·고객 자료는 공유하지 않습니다. 교차 프로젝트 안내, 학습 관리 절차를 읽으세요.

완료 이력은 시작 이벤트에서 해시 검수 후 .sodam-agent-history/로 보관할 수 있습니다. 미완료·실패·평가 근거·최근 절차는 유지합니다. 중단된 교체 복구와 재실행 방지가 포함되지만 보관·보호 기록 한도는 남습니다. 모든 과거 교훈을 무제한 검색하는 기능이 아닙니다. 예약 작업은 필요하지 않습니다.

  • 과거 기간제 승인과 현재 지속 설정은 구분합니다. 직접 끌 때까지 유지하는 설정은 자동 운영 안내를 확인하세요. 호스트 권한·프로젝트 접근 제한까지 없어지는 설정은 아닙니다.

13. FAQ — 자주 묻는 질문

Q1. 무료인가요?

저장소 코드는 Apache-2.0으로 제공됩니다. 다만 Codex, AI 모델, Context7, 네트워크 또는 다른 연결 서비스의 이용료와 약관은 별도일 수 있습니다.

Q2. 모든 플러그인을 설치해야 하나요?

아닙니다. 필요한 팀만 설치할 수 있습니다. 처음에는 docs-team 또는 업무에 맞는 팀 하나로 시작하는 것을 권장합니다.

Q3. 설치하면 자동으로 제 파일을 전부 읽나요?

이 저장소 자체에는 전체 컴퓨터를 수집하는 코드가 없습니다. 실제 파일 접근은 Codex 세션의 권한, 사용자의 요청, 연결한 도구에 따라 결정됩니다. 작업 전에 접근 범위를 확인하십시오.

Q4. API 키가 필요한가요?

이 저장소 자체는 API 키를 요구하지 않습니다. Codex와 외부 MCP·서비스는 별도 인증이나 계정이 필요할 수 있습니다. 키를 README, 테스트, 커밋 또는 프롬프트에 남기지 마십시오.

Q5. training-agent가 AI 모델을 학습시키나요?

아닙니다. 사용자 소유 SKILL.md의 업무 지침을 안전하게 수정하는 기능입니다. 모델 가중치 학습이나 파인튜닝을 수행하지 않습니다.

Q6. 플러그인 파일을 직접 고쳐도 되나요?

가능하지만 업데이트 때 덮어써질 수 있습니다. 사용자 맞춤 스킬은 사용자 소유 스킬 폴더에 복사해 관리하고, 변경 전 백업과 변경 후 검증을 권장합니다.

Q7. 데이터베이스나 로그인 기능이 있나요?

없습니다. 이 저장소는 플러그인 지침 묶음과 검증 도구입니다. 로그인·권한·DB CRUD를 제공하는 서비스가 아니므로 해당 기능 테스트도 대상이 아닙니다.

Q8. 인터넷 없이 사용할 수 있나요?

이미 설치된 Codex와 로컬 스킬은 환경에 따라 사용할 수 있습니다. 그러나 Codex 모델 접속, GitHub 다운로드, npx 패키지 획득, Context7 조회에는 인터넷이 필요할 수 있습니다.

Q9. 상업 프로젝트에서 써도 되나요?

Apache-2.0 조건을 지키면 이 저장소 코드는 상업적으로 사용할 수 있습니다. 다만 외부 서비스, 입력 자료, 생성 결과, 글꼴·이미지·데이터, 개인정보, 상표에는 별도 권리가 적용될 수 있습니다. 자세한 내용은 다음 법률 절을 확인하십시오.

Q10. 오류 보고 시 무엇을 보내야 하나요?

운영체제, codex --version, node --version, 실행 명령, 비밀을 지운 오류 메시지, 재현 순서를 보내십시오. API 키, 토큰, 개인 경로의 민감한 이름, 고객 데이터는 제거하십시오.

  2. .agents/plugins/marketplace.json과 실제 플러그인 폴더의 이름·순서를 맞춥니다.

  7. npm run validate와 npm test를 모두 실행합니다.
  8. npm pack --dry-run --json으로 배포 파일 목록을 검토합니다.
  9. README 네 파일과 PORTING_REPORT.md, NOTICE를 변경 내용에 맞게 갱신합니다.
  10. 실제 사용자 설치 테스트와 외부 통신 테스트 결과를 통과·실패·미실행으로 구분해 기록합니다.
