# 채팅 전송과 자동 학습의 확인된 제한
검증일: 2026-10-11. 적용 범위: 당시 Codex Desktop 호스트와 SoDam Autonomy Team 0.3.9의 관측 사례. 모든 버전과 모든 채팅의 동작을 보장하지 않는다.

## 무엇이 다른가
사용자가 입력창에서 보낸 요청은 호스트 진단에서 input=UserInput, turn_trigger=composer로 관측됐다. 채팅 전송 도구의 요청은 input=ResponseItem, turn_trigger=app_tool_send_message 및 delegation 문맥으로 관측됐다.
동일 승인 프로젝트에 연결된 유휴 수신 채팅에서 전송한 실제 문서 업무는 저장과 파일 검사까지 완료됐지만 새 시작 식별자와 시작 등록이 없었다. 직접 입력 업무에서는 시작 등록과 교훈 저장 및 별도 업무 반환·적용이 확인됐다. 두 번째 기존 직접 요청에는 자기 재전송이 섞였으므로 순수한 직접 입력 두 번의 비교 또는 외부 전송 해결 증거로 삼지 않는다.

## 원인 판정의 범위
시작 등록이 필요한 신뢰된 사건이 SoDam 업무 문맥으로 제공되지 않는 전송 경로를 재현했다. 설치 파일 불일치나 승인 누락으로 설명되는 사례는 아니다. 입력 형태 차이는 직접 증거이며, 호스트 내부의 훅 호출 제외 분기나 의도는 미확인이다.
entry.mjs는 시작 수신·경로 결정·처리 완료와 실패 단계를 진단한다. bridge.mjs는 호스트 session_id와 turn_id를 검증한 뒤 UserPromptSubmit에서 시작을 등록한다. 진단 로그가 없다는 사실만으로 훅 프로세스가 전혀 호출되지 않았다고 단정하지 않는다.

## 사용과 대응
- 실제 새 업무는 승인 프로젝트로 연결된 채팅의 입력창에서 요청한다. 경로 승인·연결과 훅 문맥은 매 업무의 실제 결과로 확인한다.
- 채팅 전송으로 파일 작업이 완료돼도 자동 시작·학습 저장·재사용까지 성공했다고 표시하지 않는다.
- 호스트가 신뢰 가능한 시작 사건을 제공해야 전송 경로의 자동 학습을 같은 기준으로 구현·검증할 수 있다. 현재 SoDam 도구 호출만으로 호스트의 입력 경로를 변경하거나 훅 호출을 강제하지 않는다.
- 전달 문구에서 식별자를 만들어 등록하거나 이전 업무 키를 재사용하지 않는다. 일반 도구 전달 성공을 실제 시작 사건으로 인정하지 않는다.
- 재시작은 코드 불일치가 확인됐을 때만 고려한다. 현재 연결이 최신이라는 사실과 전송 경로 지원 여부는 별개다.
- 원문 요청·도구 출력·비밀값을 학습 또는 공개 보고서에 복사하지 않는다. 지원 요청에는 버전·입력 분류·시각·단계별 유무와 마스킹된 결과만 제공한다.

## 재현과 재검증
승인·런타임 일치 확인 → 유휴 채팅에 하나의 실제 문서 업무 전송 → 수신 업무와 저장 결과 확인 → 새 훅 식별자와 프로젝트 시작 등록 대조 → 별도 후속 요청의 교훈 반환·적용 확인.
실행 중 전달·중복·자기 재전송은 별개로 검증한다. 원인 분기를 확인하기 전 정상 업무를 반복 실행하지 않는다.
코드 처리 오류가 실제로 재현되면 정본에서 최소 수정하고 잘못된 입력·만료 승인·동시 요청·중단·중복의 회귀를 검사한다. 합성 훅 시험 통과를 실제 Desktop 시작 사건 전달 성공으로 보고하지 않는다.

## 완료 조건
전송 요청마다 실제 호스트 사건과 유일한 업무 키가 연결되고 자동 dispatch, 검수한 경험 저장, 별도 요청의 경험 반환 및 적용이 확인돼야 전송 자동 학습을 완료로 판정한다. 장기 개선 및 신규 역할 품질은 실제 업무 누적과 별도 비교가 필요하다. 예약 작업·상시 데몬·승인 확대는 해결 수단으로 사용하지 않는다.
