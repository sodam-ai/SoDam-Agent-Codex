# 재시작을 미룬 상태의 실제 업무 운영 안내

## 지금 사용할 수 있는 범위
다른 채팅에서 작업 중이면 Codex 앱을 종료하지 않아도 됩니다. 최신 설치 파일로 시작한 별도 로컬 CLI·MCP에서 승인된 프로젝트의 업무·파일 검사·기록을 처리할 수 있습니다. 이미 실행 중인 Desktop MCP가 자동으로 새 코드를 읽는다는 뜻은 아닙니다.

## 순서
1. 현재 요청의 실제 시작 식별자, 프로젝트 승인, 최신 로컬 소스 일치를 확인합니다. 개발 정본과 업무 대상 복사본을 구분합니다.
2. 반환된 교훈의 출처·파일 해시·적용 조건을 확인합니다. 관련 절차만 업무에 사용하고 충돌 후보는 자동 적용하지 않습니다.
3. 실제 필요한 결과물을 만듭니다. 기존 파일은 덮어쓰지 않고 새 경로를 사용합니다. 결과물을 전체 재읽기하여 요구사항·초보자 이해도·확인 범위를 검수합니다.
4. 승인된 파일 검사 도구로 실제 산출물을 검사합니다. 실행 증거가 부족하거나 실패가 남으면 미검증으로 기록하고 성공 교훈을 만들지 않습니다.
5. 검증된 결과에만 최소 절차를 저장합니다. 다음 관련 요청에서는 저장된 교훈의 반환뿐 아니라 실제 적용과 결과도 확인합니다.
6. 역할 부족이나 개선 필요가 실제 자료로 확인될 때 기존 역할을 먼저 재사용합니다. 조건을 충족하면 후보를 시험 적용하고 비교하며, 실패하면 파일을 보존하고 복귀합니다.

## FAQ
### 재시작 없이 학습 기록을 처리할 수 있나요?
새 로컬 프로세스의 승인과 현재 실제 요청 기록이 유효하면 처리할 수 있습니다. 파일 검증만 통과했다고 성공 기록이 허용되는 것은 아닙니다. 알려진 실행 증거와 미해결 실패 없음, 내용 검수가 필요합니다.

### 새 에이전트를 지금 무조건 만들어야 하나요?
아닙니다. 기존 문서팀으로 해결되는 업무에는 역량 부족을 만들지 않습니다. 반복된 실제 역량 실패 또는 품질 기준과 맥락이 일치하는 검증된 개선 제안 등 현재 구현의 조건을 충족해야 합니다. 시험 적용은 효과 확정과 다릅니다.

### 오래된 Desktop 연결은 어떻게 되나요?
로컬 파일을 수정해도 기존 프로세스 메모리는 그대로입니다. 지금은 작업을 유지하고, 다른 세션 업무를 저장할 수 있을 때 앱을 완전히 종료·재실행합니다. 그 뒤 실제 연결의 sourceStatus=current와 프로젝트 승인을 다시 검사합니다. 단순 재실행만으로 모든 자동 학습 효과가 증명되지는 않습니다.

### 예약 작업이나 강제 권한 변경이 필요한가요?
이 업무 흐름에는 필요하지 않습니다. 승인 만료·용량 한도·동시 잠금은 자동 갱신·강제 해제하지 않습니다. 다른 프로젝트 승인 파일을 복사하지 않습니다.

### 무엇이 아직 확인되지 않았나요?
이 안내서의 파일·내용 검사와 기존 Desktop의 최신 코드 재연결, 새 채팅의 자동 호출, 신규 역할의 실제 효과, 장기 개선은 각각 별도입니다. 다른 채팅 전체와 미래 모든 작업의 성공을 보장하지 않습니다.

## 이번 실제 교훈 적용
기존 FAQ 교훈의 사용자 행동·자동 처리·오류 대처 구분을 위 순서와 질문 답변에 적용했습니다. 요구사항 정리 교훈의 정본·테스트 위치와 설치·실행·효과 구분도 적용했습니다. 역할 계획 교훈에 따라 실제 부족 증거가 없는 에이전트를 생성하지 않았습니다. 교훈의 반환만을 효과 개선으로 보고하지 않습니다.
