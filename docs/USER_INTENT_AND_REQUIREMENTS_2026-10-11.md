# SoDam-Agent-Codex 사용자 의도 및 확정 요구사항
정리 기준: 이 채팅에 제공된 요청, 정정, 승인 및 인용 보고서 전체. 접근하지 못한 다른 채팅 원문까지 조사했다고 주장하지 않는다. 요구사항 정리는 구현 완료 판정과 다르다.

## 1. 최종 목적
새 채팅에서 사용자가 실제 업무를 맡기면 SoDam-Agent-Codex가 자동으로 업무를 수행하고 경험을 축적하며, 다음 업무에 재사용하고 에이전트까지 지속적으로 개선하는 시스템.
업무 수행 → 결과 검증 → 경험·교훈 저장 → 관련 후속 업무에 적용 → 부족한 능력 판단 → 필요한 에이전트 생성·검증·적용 → 기존·신규 에이전트 학습·개선 → 효과 검증 → 유지·수정·비활성화·재활성화.
학습을 별도로 반복 지시하거나 작업 폴더마다 사용자가 수동 연결하는 운영을 줄인다. 승인된 범위에서 자동 연결한다. 예약 작업·주기적 점검·가상 성공 경험으로 실제 업무 학습을 대체하지 않는다.

## 2. 소담이 스스로 수행해야 하는 책임
- 요청과 작업 맥락을 읽고 관련 교훈과 기존 에이전트를 선택한다.
- 업무를 수행하고 실제 출력, 오류, 수정 및 결과를 확인한다.
- 검증된 최소한의 경험을 저장하고 다음 관련 업무에 반환·적용한다.
- 기존 에이전트 재사용과 개선을 먼저 검토한다. 실제 능력 부족이면 새 에이전트를 만든다.
- 생성뿐 아니라 기존·신규 에이전트의 지침·절차·도구 사용을 개선·수정·보완·보강한다.
- 필요성·품질·오류·충돌에 따라 켜기·끄기 및 재검증 후 재활성화를 관리한다.
- 개선 전후 증거, 버전 및 복구 경로를 유지한다. 실패한 변경을 성공으로 등록하지 않는다.
이는 경험·절차·역할 개선을 뜻하며 모델 자체의 가중치 재학습을 했다고 주장하지 않는다.

## 3. 사용자와 승인 경계
사용자는 실제 업무 목표, 대상, 보존 조건과 필요한 최초 승인을 제시한다. 이미 승인된 가역적 업무는 소담이 계속 처리한다. 새 비용·권한 확대·외부 전송·파괴적 변경은 기존 승인과 도구 규칙에 따라 별도로 판단한다.
과거 승인은 범위 한정이다: Desktop 다섯 훅 개별 신뢰, 실행 계정 잠금만 해제, 유효한 기존 보안 저장소 기록만 백업·일치 복구, 지정 검증 채팅 생성·후속 메시지 전송, D 테스트 복사본 활용. 다른 계정·비밀번호·권한·플러그인 전체에 대한 포괄 승인이 아니다.

## 5. 조사와 작업 방식
접근 가능한 채팅·기록·코드·설정·문서·실제 결과를 대조하여 작업 방식과 카테고리, 장점과 결함을 조사한다. 최신 정정과 명시적 제외를 우선한다. 읽지 않은 자료나 모르는 원인을 추측으로 확정하지 않는다.
문제·영향·변수·실패 가능성을 먼저 검토하고 순차적으로 필요한 범위를 끝까지 처리한다. 직접 할 수 있는 일은 사용자에게 반복해서 넘기지 않는다. 기존 기능, 데이터, 무관한 변경, 설정 및 모델을 보존하고 최소 변경을 적용한다.

## 6. 테스트와 완료 기준
설정과 package.json을 먼저 확인하고 적용 가능한 lint, type check, build, unit, integration, e2e를 실행한다.
정상·예외·경계값·잘못된 입력·실패·권한·데이터 손상·성능을 확인한다. 구현된 경우 로그인, API 성공·실패, DB CRUD, 로딩·빈 화면·오류 화면, 모바일·반응형, 브라우저·서버 오류도 확인한다. 해당 기능이 없으면 그 사실을 구분한다.
재현 → 원인 → 영향 범위 → 안전한 수정 → 관련 기능 및 전체 흐름 재검증.
기능 무력화·임의 삭제·대규모 리팩토링·실패 무시는 금지한다. 미실행·미확인은 명시한다.
설치·활성·연결·호출·업무 적용·출력 확인·학습 저장·후속 재사용·장기 효과는 별도 판정한다. 실제 종료 증거가 없는 결과는 unknown을 성공으로 바꾸지 않는다. 시작 식별자를 만들거나 다른 요청에서 빌리지 않는다.

## 7. 보안과 데이터
키·토큰·비밀번호·환경 파일·인증서·개인 키·DB 정보·개인정보·고객 자료·비공개 정보가 코드, 학습, 로그, 문서, 시험, 커밋 및 빌드 결과에 노출되지 않게 점검한다.
학습에는 업무에 필요한 최소 교훈을 저장한다. 권한과 프로젝트 경계를 지키며 원문이나 민감 출력의 무분별한 수집을 피한다. 개인 메모리·볼트·Codex 설정·AGENTS.md 변경은 별도 규칙과 승인을 따른다.

## 8. 초보자용 문서
프로젝트 최상위에 한국어 기본 README와 영어 문서를 Markdown 및 HTML로 작성·유지한다. 두 언어의 구조·의미 및 각 언어의 Markdown·HTML 내용은 일치한다.
목차, 사전 준비물, 필요 프로그램, 다운로드, 설치, 빠른 시작, 실행·사용·작동 방법, 명령어, 접을 수 있는 업데이트 요약, 파일 위치, 워크플로우, 아키텍처, 보안·데이터 흐름, 오류 대처, FAQ, 권리·라이선스·상업적 이용을 구체적이고 쉬운 말로 설명한다. 실제 구현과 문서를 대조한다.

## 9. 권리와 상업적 이용
기존 라이선스를 기준으로 LICENSE, NOTICE, 한국어·영어 README 및 가이드를 일관되게 정리한다. Apache License 2.0 공식 본문과 SoDam AI Studio 권리자·연도를 확인한다. 임의로 새 권리를 보장하거나 라이선스를 변경하지 않는다.
코드·문서·이미지·아이콘·폰트·샘플·데이터·프롬프트·AI 생성물·외부 API·SDK·의존성의 권리와 출처를 점검한다. 수정·복제·포크·재배포·판매·서비스 운영·교육·납품의 허용 조건과 외부 약관·요금·권리를 안내한다. 불확실한 해석은 법무/전문가 검토 필요로 표시한다.

## 10. GitHub 반영과 설치
최종 정리·보안·검증 후 의미 있는 단위로 커밋하고 작업 브랜치에 push한다. main/master 직접 push는 하지 않고 PR 및 조건 충족 시 merge하여 메인 README 반영을 확인한다. CHECKPOINT.md는 커밋·push하지 않는다.
한국어 About, 검증된 홈페이지 URL, 실제 기능·기술에 맞는 공개 가능한 Topics를 점검한다. 공개 전환과 이후 노출 상태를 확인한다. 이후 명시 요청에 따라 push 완료 후 Release도 수행 대상이다.
CLI·Desktop 설치본과 정본, 실제 로드된 MCP 코드의 일치를 확인한다. 훅 정의와 개별 신뢰를 점검한다. 설치·시험 통과만으로 실제 훅과 자동 학습 완료를 주장하지 않는다.

## 11. 현재 해석과 검증 한계
최우선은 앞으로 직접 시작하는 새 채팅의 실제 업무 흐름이다. 다른 채팅으로 도구가 전달하는 요청의 시작 누락은 별도 경로 문제이며 전체 목적을 그 문제로 축소하지 않는다.
플러그인이 수신한 입력 처리 결함은 정본에서 수정한다. 호스트가 전달하지 않은 이벤트는 플러그인만으로 전달됐다고 보장하지 않는다.
실제 업무의 저장·후속 적용과 모든 새 채팅의 자동 실행, 에이전트 전체 수명주기, 장기 개선 효과는 각각 증거가 필요하다. 장기 효과는 실제 업무가 축적된 후 판단한다.
이 문서는 이해한 요구사항을 기록한 것이며 모든 기능의 구현·설치·자동 실행 완료 증명서가 아니다.
