# 채팅 간 메시지와 작업 중 학습의 확인 범위

확인일: 2026-10-11. 구현 기준: autonomy-team 0.3.9.

## 일반 요청과 채팅 간 메시지를 구분하세요

이번 일반 자연어 요청에서는 실제 UserPromptSubmit 문맥에 승인된 작업 위치와 turnKey가 전달됐고, dispatch가 이전 문서 업무의 교훈을 반환했습니다. 교훈 출처는 event-866f1e2a9c577ea49191bea09d12cf21이며, 증거 파일의 해시가 다시 확인된 뒤 반환됐습니다.

반면 검사 대상 채팅으로 전송한 후속 메시지에서는 작업 위치와 기존 회상은 전달됐지만 현재 작업의 turnKey가 없었습니다. 해당 채팅의 두 실제 작업 식별자를 정본 bridge.mjs와 같은 방식으로 대조한 결과, 승인 프로젝트 hooks.json에 대응 시작 작업이 없었습니다. 이 관측은 해당 실행 사례에 한정합니다. 모든 Desktop 버전과 모든 전송 경로가 시작 훅을 생략한다고 일반화하지 않습니다.

## 무엇이 완료됐고 무엇이 남았나요?

- 실제 빠른 시작 문서 작성, 의미 검수, 파일 검사, 교훈 저장이 완료됐습니다.
- 별도 사용자 요청의 dispatch에서 같은 교훈 출처가 반환됐습니다. 후속 문서 검수에 현재 상태와 과거 기록 분리, 원문 보존, 검수 범위 표시 절차를 적용했습니다.
- 다른 채팅의 문서 작성 성공은 해당 채팅의 신규 학습 저장 성공이 아닙니다.
- 장기 품질 개선과 모든 훅의 호스트 실행은 별도 검증 대상입니다.

## 안전한 대응

1. 현재 요청의 훅 문맥과 승인 작업 위치를 확인합니다. 이미 정상인 일반 요청 경로를 사용할 수 있습니다.
2. 시작 훅 문맥이 없는 전송 요청은 허용된 실제 업무만 수행하고 신규 학습 저장은 미실행으로 보고합니다.
3. 임의 turnKey를 만들거나 다른 요청의 식별자를 빌리지 않습니다. 원문을 저장해 시작 이벤트를 재생하지 않습니다.
4. 호스트의 이벤트 전달 여부를 먼저 확인합니다. 시작 이벤트가 실제 전달됐는데 플러그인 처리가 실패한 증거가 있을 때 해당 코드만 수정합니다.
5. 이미 최신인 MCP를 반복 재설치하거나 승인 범위를 확대하거나 예약 작업으로 우회하지 않습니다.

## 구현 근거

plugins/autonomy-team/hooks/entry.mjs는 호스트 이벤트를 승인 작업 위치로 연결합니다. runtime/bridge.mjs는 UserPromptSubmit에 작업을 등록하고 session_id와 turn_id로 turnKey를 계산합니다. dispatch는 이미 등록된 실제 작업만 받습니다. SessionStart 회상은 신규 작업 등록을 대신하지 않습니다.

이번 조사에서 시작 이벤트가 플러그인에 도착했는데 처리되지 않았다는 호스트 로그 증거는 확보하지 못했습니다. 따라서 호스트 호출 누락과 훅 처리 실패의 최종 원인 판정은 미확인입니다. 권한 검사나 기존 보호 조건을 약화하는 수정은 하지 않았습니다.
## 2026-10-11 같은 채팅 입력 경로 비교 결과

같은 검증 채팅에서 채팅 간 전송 요청과 사용자의 직접 입력 요청을 비교했습니다. 전송 요청은 승인 유효·MCP 최신 상태에서도 현재 turnKey가 없고 대응 시작 등록도 없었습니다. 직접 입력 요청은 실제 시작 식별자를 받았고 dispatch, 기존 교훈 반환 및 실제 적용, 파일 검수, verified finish가 완료됐습니다. 실제 C 작업 디렉터리의 해당 세션은 승인된 D 테스트 프로젝트로 연결되어 저장됐습니다.

직접 입력 업무의 저장 경험은 event-719fc5e356951ba299b32aa467f46e2f입니다. 증거 FAQ의 SHA-256은 7d00a4fad912910d453b751e86cc6da733c13e5ea1ba33e4f592864295ead2bf이고, 재읽기 및 MCP 파일 검사 결과와 저장 기록이 일치했습니다. 기존 빠른 시작 교훈 event-866f1e2a9c577ea49191bea09d12cf21의 사용자 행동·자동 처리·오류 대처 구분을 해당 FAQ에 적용했습니다. 저장된 신규 교훈은 일본어로 기록되어 한국어 기본 원칙과의 표현 일관성에 주의가 필요합니다. 기존 학습 기록을 임의로 수정하지 않았습니다.

따라서 이 채팅의 직접 입력을 통한 작업 중 학습과 이전 업무 교훈 재사용은 확인됐습니다. 자동 전송 경로의 시작 등록 누락은 남아 있으며 호스트 내부 원인이나 일반적인 지원 여부를 확정한 것은 아닙니다. 플러그인 진입 후 처리 실패 증거는 확보하지 못했으므로 권한·시작 등록 조건을 약화하는 코드 수정은 하지 않았습니다. 직접 입력 경로는 지금 사용할 수 있습니다. 동일 검증을 위해 반복 설치나 재시작은 필요하지 않습니다.

정본에서 npm run validate는 종료 코드 0으로 플러그인 12개·스킬 56개·매니페스트 24개를 확인했습니다. 첫 npm test는 test/areas.mjs의 MCP 자식 프로세스 종료 상태가 null인 오류로 실패했습니다. 해당 호출의 제한은 5초이며 정확한 종료 원인은 이 출력만으로 확정되지 않습니다. node test/areas.mjs 독립 실행 23개 그룹 및 전체 npm test 재실행 18개 스크립트는 모두 종료 코드 0으로 통과했습니다. 시간 제한과 판정 기준을 변경하지 않았고 첫 실패 기록도 보존했습니다. 간헐적 실행 문제의 완전한 제거를 보장하지 않습니다.

공식 훅 문서 https://learn.chatgpt.com/docs/hooks#userpromptsubmit 는 사용자 프롬프트와 현재 turn_id를 설명하지만 이 채팅 간 전송 도구의 이벤트 발생을 보장하는 근거는 확인하지 못했습니다. Desktop 로그의 hook 알림만으로 특정 플러그인의 특정 요청 성공을 판단하지 않았습니다. 장기 개선, 모든 채팅 및 모든 입력 경로는 이번 검증 범위 밖입니다. 예약 작업은 만들지 않았습니다.
