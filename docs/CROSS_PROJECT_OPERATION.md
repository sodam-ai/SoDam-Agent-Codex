# 서로 다른 프로젝트에서 자동 운영하기

이 문서는 현재 구현된 기능과 아직 검증하지 않은 범위를 구분합니다. 예약 작업이나 별도 상시 프로세스를 만들지 않습니다.

## 작동 흐름

1. 실제 새 요청의 신뢰된 시작 훅이 현재 작업 위치를 확인합니다.
2. 기존에 승인한 작업 영역 안이면 프로젝트를 자동 연결합니다. 영역 밖·제외 폴더·만료·한도 초과는 승인하지 않습니다.
3. 모델이 현재 업무를 분류합니다. 기존 13개 전문 경로에 맞지 않으면 `kind:general`, `route:autonomy-team`을 사용합니다. 일반 경로는 같은 스킬을 반복 호출하지 않고 실제 업무를 수행합니다.
4. 실제 시작 식별자로 dispatch하면 프로젝트 내부 교훈을 조회합니다. 현재 업무의 `contextTags`가 있고 별도 공유 승인이 있으면 다른 연결 프로젝트의 적합한 공통 절차도 조회합니다.
5. 업무·산출물·실행 결과를 검수한 뒤 finish합니다. 실제 업무에서 확인한 절차만 저장합니다.
6. 기존 에이전트 생성·시험 적용·평가·비활성화·복귀 절차는 그대로 동작합니다. 공유된 교훈 자체가 에이전트 생성·독립 실행·효과 확정의 증거는 아닙니다.

## 공유 승인과 끄기

기존 작업 영역 승인은 파일 작업 범위의 승인입니다. 다른 프로젝트의 절차 재사용은 별도로 관리합니다. 기존 영역은 기본적으로 공유가 꺼져 있습니다. 일반 훅과 MCP는 공유 승인을 만들거나 갱신하지 않습니다.

관리자는 실제 영역 ID를 `area-inspect`로 확인하고 해당 승인 영역 안에 JSON 요청 파일을 작성합니다. 아래 예시의 영역 ID는 실제 값으로 바꿔야 합니다.

```json
{"authorize":true,"areaId":"실제 32자리 영역 ID","enabled":true}
```

```powershell
node "설치본의 실제 runtime/cli.mjs 경로" area-sharing "승인된 작업 영역 절대 경로" "요청 파일 상대 경로.json"
```

끄려면 동일한 요청의 `enabled`를 `false`로 바꿉니다. 끄기는 승인 만료·철회 후에도 가능하며 저장된 경험을 삭제하지 않습니다. 켜기는 만료를 갱신하지 않습니다. 조회하는 영역과 원본 영역 **모두** 공유가 켜져 있어야 합니다. 프로젝트별 승인만 있는 기존 독립 저장소는 이 공유에 자동 편입되지 않습니다.

공유 동의는 승인 등록 파일과 분리된 `procedure-sharing.json`에 저장합니다. 기존 `registry.json`에는 새 항목을 추가하지 않아 구버전의 승인 검사를 보존합니다. 새 버전은 영역 ID·폴더 식별값·기존 승인 유효성을 함께 확인합니다. 공유 파일이 손상되면 공유만 거부하며 승인 등록 파일을 덮어쓰거나 자동 복구하지 않습니다. 구버전은 공유 기능을 실행하지 않으므로 설치 반영과 새 프로세스 확인은 여전히 필요합니다.

중간 개발 버전의 승인 파일에 남아 있는 `shareProcedures` 항목은 읽기 호환을 유지하지만 별도 공유 동의로 간주하지 않습니다. 새 코드가 해당 항목을 자동 삭제·이전하지 않습니다. 구버전은 그 항목을 거부하므로 이미 남아 있다면 명시적인 복구가 필요합니다.

## 어떤 교훈만 공유하나요?

공통 사용이 가능한 절차에는 `lesson.portable:true`, 최소 한 개의 `applicability.required` 태그, 의미 검수 `semanticReviewed:true`, 개인정보·프로젝트 정보 검수 `portableReviewed:true`가 필요합니다. 실제 verified finish 경로를 거쳐야 합니다. 실패 가설·미확인 결과는 성공 교훈으로 공유하지 않습니다.

모델은 고객명·프로젝트명·개인정보·원문·로컬 경로·비공개 정보를 빼고 적용 조건을 구체적으로 작성해야 합니다. 자동 검사는 대표적인 경로·이메일·전화번호·비밀 값·실행 지시를 거부하지만 모든 개인정보를 찾아내는 보장은 아닙니다. 안전성을 확인하지 못하면 `portable`을 생략하고 해당 프로젝트 안에만 보존합니다.

원본 파일과 내용은 복사하지 않습니다. 공유 응답에는 절차·적용 조건·불투명한 출처 ID·증거 해시만 포함합니다. 출처 파일 경로는 반환하지 않습니다. 조회 때 원본 증거의 변경·누락, 승인 만료·철회, 제외 범위, 프로젝트 교체를 다시 확인합니다. 역할에 귀속된 교훈은 원본 역할이 confirmed이고 파일 검사를 통과할 때만 공유합니다. pilot·disabled 역할은 제외합니다.

최대 16개 연결 프로젝트, 프로젝트당 최근 24개 기록, 공유 절차 최대 3개(프로젝트 내부 교훈 최대 3개와 별도)를 조회합니다. 증거 파일은 각 256 KiB 이하, 한 조회에서 총 4 MB 이하입니다. `sharedSelection`은 승인 부족·조건 부족·조회 실패·잘림·검사 수를 구분합니다. 파일 검사 성공과 업무 효과는 별개입니다.

## 현재 완료 조건과 한계

- 일반 업무 경로와 별도 동의 기반 프로젝트 간 절차 조회 코드를 구현했습니다.
- 기존 승인·사건 식별자·실패 판정·원본 보존·에이전트 생명주기 기준을 유지합니다.
- 새 채팅은 호스트가 실제 시작 훅과 식별자를 전달해야 합니다. 채팅 전송 도구의 사건 누락을 가짜 시작 기록으로 보완하지 않습니다.
- 승인하지 않은 임의 프로젝트, 프로젝트 없는 채팅의 자동 저장 위치, 모든 새 채팅에서의 실제 작동, 공통 에이전트의 생성·개선·켜기/끄기 전체 운영은 완료로 주장하지 않습니다.
- 테스트용 격리 HOME의 기술 시험은 실제 사용자 업무나 장기 개선 효과를 증명하지 않습니다. 설치본 반영 및 실제 서로 다른 프로젝트의 별도 요청 검증은 추가 확인이 필요합니다.

이 프로젝트는 모델 가중치를 학습하지 않습니다. 작업 모델이 검증된 경험에서 제한된 절차를 추출하고 다음 업무에 적용하는 방식입니다.
