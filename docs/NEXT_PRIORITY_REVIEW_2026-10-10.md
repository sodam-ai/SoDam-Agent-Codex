# 현재 기준 권고 2026-10-10

목적: 실제 업무 중 경험 추출, 조건별 재사용, 증거 기반 역할 개선. 예약 작업 없음.

현재 확인: 정본 runtime의 stale 쓰기 차단, 고정 문법 증거 검증, 조건별 recall, 역할 비교 및 보관 절차를 확인했다. 이전 전체 회귀 결과는 통과 기록이며 이번에는 전체 테스트를 재실행하지 않았다. 연결 Desktop은 changed인데 dispatch를 수락했다. 구형 프로세스에는 새 차단 코드가 적용되지 않는다. 이후 쓰기는 새 CLI만 사용한다.

순서
1. 최종 설치 묶음 고정 및 Desktop 재연결, current/신규 도구 노출/승인 유효 확인.
2. 실제 D 업무에서 자동 시작, 작업 결과 의미 검수, 파일 검사, 학습 저장, 후속 요청 재사용을 각각 추적. 검사만 성공한 경우 전체 기능 성공으로 확대하지 않는다.
3. 현재 Bash 평문의 종료 정보 누락 보완: 실제 호스트의 지원되는 구조화 결과를 조사하고 어댑터를 최소 수정. 종료값 없는 기존 unknown은 유지.
4. 고정 파서 실제 시간 초과, 권한 거부, 강제 종료 및 최대 입력 부하 시험. 단계 증거까지 이어지는 통합 회귀 추가.
5. 현재 조건별 교훈 재사용·중복 제거·근거 해시와 보관 기능 유지. 적용/제외 이유를 비민감한 메타데이터로 설명하도록 보강. 의미 충돌 자동 판정을 주장하지 않는다.
6. 실제 반복 업무 비교로 개선 효과 판단. 기존 역할 우선, 반복 역량 실패가 확인될 때만 새 역할 pilot. 동일 기준·조건·절차 증거·서로 다른 비교 업무 요구. 나빠지면 비활성/복귀하고 기록 보존.

이유: 가장 큰 빈틈은 역할 수가 아니라 최신 실행 및 결과 판정의 신뢰도다. 거짓 성공 학습이 쌓이면 자동 개선이 오류를 재사용하므로 먼저 실제 증거 연결을 안정화한다. 장기 효과는 실제 업무로만 평가한다. 이번 검토는 내부 검토이며 전 코드 독립 감사나 완전 무결성을 보장하지 않는다.
