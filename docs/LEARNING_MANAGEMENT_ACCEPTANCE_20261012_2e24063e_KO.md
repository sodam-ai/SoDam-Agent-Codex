# 업무 중 학습 관리자 보강·검증 결과

검증일: 2026-10-12. 이 문서는 코드·기술 시험·설치·실제 자동 운영을 구분한다.

## 목적과 개발 위치

새 채팅에서 서로 다른 프로젝트·업무를 맡겨도 승인된 범위에서 업무 파악, 관련 교훈 적용,
실행, 검수, 교훈 저장, 필요 시 역할 생성·개선·활성화·비활성화·복구를 수행하는 것이 목적이다.
개발 정본은 <project-root> 이며,
테스트 복사본은 <test-project-root> 이다.
예약 작업은 생성하지 않았다. 모델 자체의 가중치 훈련을 구현했다고 주장하지 않는다.

## 원인과 최소 변경 이유

- 업무 학습은 호스트 모델의 의미 판단과 로컬 런타임의 증거·저장·역할 관리가 함께 필요하다.
- 업무별 능력 부족(gap)과 맥락(contextTags)이 없으면 역할 생성이나 조건부 공유가 제한되는 것은 보호 조건이다.
  실제 업무의 근거에서 이 조건을 판단하도록 안내를 보강했으며, 가짜 부족 사항·태그를 만들지 않는다.
- 학습 관리용 스킬은 의미 판단을 안내한다. 호스트가 전달하지 않은 시작 사건을 만들어내거나,
  실행 중인 MCP를 새 코드로 재로딩하는 기능을 대신할 수 없다.
- procedureExecutionVerified:false는 역할/교훈 반환이 실제 실행의 증거가 아님을 유지한다.
- 환경·권한 실패를 에이전트 능력 부족으로 학습시키지 않는다. 기존 역할·조건·한도는 보존했다.

- npm test: 일반 환경에서 19개 시험 스크립트 전체 통과(exit 0).
- npm run validate: 플러그인 12개·스킬 56개·매니페스트 24개 검사 통과(exit 0).

- node test/bridge.mjs: 변경 관련 27개 그룹 통과.

- 잘못된 입력, 승인 없음·만료, 맥락 불일치, 실패·unknown 도구 결과, 증거 변조,

  파일 교체 실패를 한 번 반복한 사실도 남긴다. 기능·시험을 약화하지 않고 임시 파일 위치 및 실행 환경을 변경해 통과했다.
- 일반 실행 환경의 성공을 샌드박스 문제가 해결됐다는 뜻으로 확대하지 않는다.
- 별도 lint/typecheck/build 명령은 프로젝트에 정의된 검사를 기준으로 구분하며, 해당 이름의 별도 실행은 미실행이다.
- 이번 변경은 브라우저·서버·로그인·DB 기능을 추가하지 않았다. 화면/실서비스 콘솔/장기 성능 검증은 미실행이다.

## 설치본과 MCP

Global, CLI, Desktop 설치본 3곳에 변경 플러그인 파일 4개씩만 반영했다.
12개 파일의 SHA-256 해시는 정본과 일치한다. 다른 플러그인·설정·훅 신뢰·승인은 변경하지 않았다.
설치 전 백업과 파일 해시는 <private-installation-backup>/manifest.json 에 있다.

새 설치본 MCP에서 initialize, tools/list, inspect_runtime 실제 호출 성공:
sourceStatus=current, authorization=valid, workEligible=true.
연결된 기존 Desktop MCP의 실제 진단은 sourceStatus=changed, nextAction=reconnect-runtime.
두 결과는 다른 프로세스의 결과이다. 디스크 설치만으로 기존 프로세스의 재연결을 주장하지 않는다.

## 완료 범위와 남은 사항

완료: 정본 보강, 기술 회귀 검증, D 격리 복사본 검증, 설치본 파일 반영, 새 설치본 MCP 호출.
미완료: 기존 Desktop MCP 재연결. 제공된 도구에 재연결 기능이 없어 실행 중인 앱을 종료하지 않았다.
미확인: 이번 보강 이후 새 직접 입력 채팅·다른 실제 프로젝트의 자동 실행·학습 저장·교훈 적용·역할 효과.
기존 직접 입력 문서 업무의 저장·재사용 증거는 유지하되 모든 새 프로젝트의 증거로 확대하지 않는다.
채팅 전송 시작 식별자 누락의 호스트 내부 원인과 장기 개선 효과는 미확인이다.
같은 실패 전송 검사는 반복하지 않았다. 실제 업무가 누적되어야 하는 장기 효과를 현재 통과로 처리하지 않는다.

이번 턴의 전체 자동 운영 결과는 unverified로 마감한다. 성공 교훈·공유 교훈·가짜 식별자는 생성하지 않는다.
보안 검사는 입력·증거·권한·오류 정보 보호의 회귀 범위이다. 전체 저장소의 새로운 민감정보 전수 점검 완료를 뜻하지 않는다.
